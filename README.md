# Kestrel DROP 电脑下载管理

在电脑上扫描 Kestrel DROP、下载历史数据、保存到本地数据库，再按需要导出成 Excel 能打开的 CSV。

**日常只需要：打开软件 → 选设备 → 按 Enter 下载 → 按 e 导出。** 不需要自己操作数据库、计算记录编号或拼接 CSV。

当前支持 **DROP D3**。D1、D2 尚未适配；扫描到候选设备不代表可以下载。蓝牙协议来自逆向分析，仍属于实验性实现。适用 macOS / Linux；Windows 暂不支持本项目的 curses 界面和文件锁。

## 第一次使用

### 1. 准备电脑和软件

需要电脑蓝牙，以及 uv。uv 是运行 Python 项目和安装依赖的小工具；SQLite 使用 Python 自带的库，不需要另装数据库服务器。

先打开 macOS 的“终端”，输入：

```bash
uv --version
```

如果提示找不到 uv，按 [uv 官方安装说明](https://docs.astral.sh/uv/getting-started/installation/)安装，完成后重新打开终端。已经安装 Homebrew 的 Mac 可以使用 `brew install uv`。

然后进入项目文件夹并启动。下面假定项目位于“下载”文件夹：

```bash
cd ~/Downloads/kestrel-drop-protocol
uv run kestrel.py
```

第一次运行可能需要联网下载 Python 或蓝牙依赖，稍等即可。也可以在 Finder 中双击项目里的 **Kestrel.command**。如果你的文件夹位置不同，`cd` 后使用实际路径。

### 2. 准备设备

1. 把 D3 放在电脑附近。
2. 在手机 Kestrel LiNK 中断开这个设备，并关闭手机端连接。
3. 打开电脑蓝牙；系统询问终端的蓝牙权限时允许访问。
4. 将终端窗口拉大。建议至少 100 列 × 24 行，最低 68 列 × 18 行。

### 3. 第一次下载

1. 在界面按 `s`，等待扫描结束。
2. 用键盘 ↑↓ 选中自己的 D3 序列号。
3. 按 `Enter`，开始下载。
4. 等到界面提示完成。已验证的数据会自动进入 SQLite，记录编号也会保存下来。

已有本地档案会在启动时自动显示；没有扫到设备时也能查看已保存的数据。

扫描显示的是广播信息。软件连接后会再读取序列号和型号，核对通过才发送历史读取指令。对于未命名的候选设备，按 `n` 输入机身序列号；BLE 地址一般保持界面提供的值即可。

## 每天怎样下载和导出

### 更新数据

再次打开软件，选择同一设备，按 `Enter` 即可。软件自动判断：

- 没有档案：读取设备最早仍保留的历史，建立新档案。
- 已有档案：从上次保存的记录编号继续，只下载新增记录。

多台设备可以按 `a`，按顺序同步所有已有本地档案的设备。单台失败会继续处理下一台。还没建立档案的新设备，需要先扫描并单独下载一次。

下载过程会明确显示扫描、连接、核对设备、查询、接收、校验、保存和入库阶段。接收条数达到预计数量时，仍需等待设备完成确认与入库，不能据此提前拔掉设备或认定任务完成。

结束后显示“下载结果”：**本次新增、累计条数、未确认条数与时间范围**。可以直接按 `v` 查看已保存记录，按 `e` 导出，按 Enter 返回设备列表。没有新数据会显示“已经是最新”；设备没有历史时会显示“设备暂无记录”。

发生错误时先显示中文原因和下一步建议。可安全重新发起的任务会显示 `r` 重试入口；设备不匹配、档案冲突等错误不会提供一键重试。按 `l` 可查看技术详情。软件不会自行反复连接或跳过校验。

界面中的“附近”只表示本次扫描看到了广播；不是持续在线检测。“已入库”是可查询的完整记录，“未完成”是已落盘但尚未确认整个传输完成的记录。

### 查看记录

选择设备后按 `v`，显示最近 100 条已入库记录，最新记录在最上方。使用 ↑↓ 滚动，按 Esc 或 `q` 返回。

### 导出给 Excel

1. 选择设备后按 `e`。
2. 第一项是输出路径，默认放到 `archive/exports/`，一般直接按 Enter。
3. 开始时间不需要限制就留空，按 Enter。
4. 结束时间不需要限制也留空，按 Enter 提交。
5. 等待提示“已导出”，到输出目录打开 CSV。

时间可以写成 `2026-10-22`，也可以写成 `2026-10-22 12:30:00`。**结束时间只写日期时，包含当天整天。** 指定到时分秒时包含该时刻。时间采用设备自身的本地时钟，不会自动换成 UTC 或电脑时区。

导出文件使用 UTF-8 BOM，方便 Excel 识别中文编码。文件已存在时会拒绝覆盖；换一个文件名即可。导出只读数据库，不会改变设备数据或增量游标。

### 按键速查

| 按键 | 作用 |
| --- | --- |
| ↑ / ↓ | 选择设备或滚动记录 |
| Enter / d | 下载选中设备：首次全量，以后增量 |
| s | 扫描附近设备 |
| a | 依次同步全部已有档案的设备 |
| v | 查看最新记录 |
| e | 导出 CSV |
| b | 备份 SQLite 数据库 |
| r | 校验档案、补入库并刷新列表 |
| n | 手动输入设备序列号 |
| i | 导入本工具以前下载的完整 CSV 和原始元数据 |
| c | 取消当前任务，保留已落盘数据 |
| l | 查看完整日志；可用 ↑↓、PgUp、PgDn 滚动 |
| ? | 查看帮助 |

注意：主界面的 `r` 是刷新；下载结果页中仅在可重试错误时，`r` 才表示重新发起本次操作。首次下载重试仍可能重新读取完整历史。

输入表单中用 Tab / ↑↓ 切换字段，Enter 进入下一项或提交，Ctrl+U 清空当前项，Esc 取消。

## 数据到底保存在哪里

默认保存在**项目文件夹内的 `archive/`**。使用 `--data-dir` 指定其他位置时，数据库、档案、默认导出和默认备份都会一起放到那个目录。

| 路径 | 用途 | 日常需要手动操作吗 |
| --- | --- | --- |
| `archive/library.sqlite` | 所有设备的统一 SQLite 查询库 | 不需要，软件自动维护 |
| `archive/exports/` | 通过 TUI 导出的 CSV | 可以打开、复制给别人 |
| `archive/backups/` | 通过 b / backup 生成的数据库快照 | 建议定期复制到其他磁盘 |
| `archive/<序列号>/history.csv` | 新设备的完整、已提交下载档案 | 不要手动编辑 |
| `archive/<序列号>/history.csv.json` | 首次完整下载的原始证据 | 保留 |
| `*.sync-state.json` | 下一条记录编号、已提交条数、CSV 校验和 | 保留 |
| `*.pending.csv` / `*.pending.json` | 增量传输的断点恢复材料 | 保留，中断后尤其不能删除 |
| `*.unconfirmed-*.bin` | 中断时尚未发布检查点的原始尾部证据 | 保留，软件不会把它冒充已确认记录 |
| `archive/.downloads/` | 首次下载的暂存与中断证据 | 不要当作完成数据导出 |
| `archive/.imports/` | 历史导入的暂存或失败证据 | 保留以便排查 |
| `*.lock` / `.device-*.lock` | 防止同一档案被同时写入的锁文件 | 文件存在不代表正在下载，无需手动删除 |

这个工作目录里以前已有的设备档案继续使用 `archive/d3_2866855.csv`，没有为了统一命名而搬动它；新建的档案采用每个序列号一个子目录。软件同时识别这两种布局。

可能看到 `library.sqlite-wal` 和 `library.sqlite-shm`，这是数据库运行时的配套文件，关闭连接后可能消失。不要在程序运行时单独删除它们。

`data/originals/` 保存本工作目录的历史原始下载，`data/analysis/` 保存早期抓包分析。它们与日常运行的 `archive/` 分开；不是另一个自动更新的数据目录。从 Git 新克隆项目时，这些个人资料不会随代码一起出现。

## CSV 和 SQLite 分别做什么

建议同时保留，职责分开：

```text
D3 蓝牙历史
    ↓ 每个通过 CRC 的块先落盘，再回复设备
CSV 暂存 / 下载恢复档案
    ↓ 收到完成游标，校验记录、顺序和游标
已提交 CSV + 同步状态
    ↓ 一次 SQLite 事务：记录、设备状态、入库批次一起提交
archive/library.sqlite
    ├── 界面记录预览
    ├── 时间筛选与 CSV 导出
    └── 数据库备份
```

SQLite 用于统一查询和管理，不再靠 Excel 拼接多份文件。库内有三张主要表：

- `devices`：设备型号、序列号、起止游标、记录数和来源校验和。
- `observations`：观测时间、测量值、原始 21 字节记录和绝对游标。
- `ingestion_batches`：每次新快照入库的时间、增加条数和来源校验和。

每条记录用 **“设备序列号 + 绝对游标”** 唯一识别。游标就是设备为历史记录使用的编号；它可能很大，不等于电脑上保存的记录条数。

相同时间戳可能属于两条真实记录，因此不会按时间去重。重复启动、刷新和补入库不会再次插入相同记录。已经入库的同一游标若出现不同内容，软件会报告冲突，不会偷偷覆盖。

**SQLite 与 CSV 不是跨文件的同一个事务。** 如果 CSV 已成功提交，但电脑在 SQLite 入库前中断，下一次启动、刷新、预览或导出会重新校验 CSV 并补入库。未确认完成的 pending 记录不会进入查询库。CSV/JSON 仍承担蓝牙下载的恢复职责，因此暂时不能只保留数据库就继续下载。

更详细的实现和 SQL 示例见 [存储设计](docs/storage.md)。

### 导出列怎么看

| 列名 | 含义 |
| --- | --- |
| `serial` | 设备序列号 |
| `absolute_cursor` | 这条记录的绝对编号 |
| `timestamp_device_local` | 设备本地时间，没有时区偏移 |
| `temperature_c` | 温度，℃ |
| `relative_humidity_pct` | 相对湿度，% |
| `station_pressure_hpa` | 站点气压，hPa，不是海平面修正气压 |
| `heat_index_c` / `dew_point_c` | 热指数 / 露点，℃ |
| `density_altitude_m_raw` | 解码的密度高度，m |
| `density_altitude_m_official_integer_estimate` | 为与官方整数显示比对保留的估计值 |
| `record_hex` | 原始记录的十六进制表示，供追溯 |
| `block` / `position_in_block` | 当次传输中的块编号和块内位置 |
| `unknown_byte` | 尚未确认含义的原始字段，不作为已知测量使用 |

## 已有数据怎样升级入库

### 已经在使用这个项目

启动 TUI 即会校验已有档案并自动入库；不会重新下载，也不会删除旧 CSV。如果只想在终端完成升级：

```bash
uv run kestrel.py db
```

看到 `integrity: "ok"` 以及设备、记录统计即表示数据库检查通过。重复运行不会重复增加记录。

### 只有本工具以前下载的完整 CSV

需要成对准备：

```text
my_history.csv
my_history.csv.json
```

然后按 `i`，输入 CSV 路径；元数据路径留空时自动使用旁边同名的 `.csv.json`。也可以：

```bash
uv run kestrel.py import /实际路径/my_history.csv
```

软件复制并验证文件，再建档入库；源文件保留。已有同序列号档案时拒绝再次导入，平时更新应使用“下载”，不要重复“导入”。

**Kestrel LiNK 官方 CSV 不能直接作为增量档案导入。** 它没有本工具要求的原始记录与绝对完成游标。文件扩展名相同不代表数据格式相同。

## 备份与换电脑

### 平时保存一份可查询的数据备份

在 TUI 按 `b`，或执行：

```bash
uv run kestrel.py backup
```

默认保存在 `archive/backups/`，输出会显示完整路径。软件使用 SQLite 备份接口生成一致的数据库快照，并检查完整性，已有备份不会被覆盖。可以复制这个生成完成的 `.sqlite` 文件到其他磁盘。

它包括设备、已入库观测和入库批次，**不包括**中断暂存、CSV 下载档案或其他文件。只恢复数据库可以预览和导出，但不能直接继续蓝牙同步。

### 要换电脑，并继续下载

1. 等当前任务结束，关闭 TUI、下载命令及其他正在操作这个档案的程序。
2. 备份**整个 `archive/` 文件夹**，包括隐藏目录、CSV、JSON 和数据库配套文件。
3. 新电脑准备项目代码与 uv。
4. 将完整的 `archive/` 放回项目根目录，或用 `--data-dir` 指向恢复的目录。
5. 先运行 `list` 检查条数和状态，再继续下载。

```bash
uv run kestrel.py --data-dir /实际路径/恢复的档案目录 list
```

不要在下载或入库过程中仅复制正在使用的 `library.sqlite`。运行中的数据库备份请使用 `backup`；完整档案的文件复制请在所有相关程序停止后进行。备份机制背景见 [SQLite 官方说明](https://www.sqlite.org/backup.html)。

若只有数据库快照，可将它放在一个新目录并命名为 `library.sqlite`，通过 `--data-dir` 预览、导出已有数据。软件会提示“仅有数据库副本”，并拒绝直接继续下载，避免把不完整恢复当成正常续传。

## 常见问题

### 扫描不到设备

先确认手机 LiNK 已断开；检查电脑蓝牙和终端蓝牙权限，靠近设备后重试。可增加扫描时间：

```bash
uv run kestrel.py scan --timeout 30
```

未命名的 DROP 服务广播只作为候选显示，需要提供正确序列号。D1、D2 当前不支持下载，不要把它们当成 D3。

### 下载中断了，要不要删除文件重来

不用，也不要删除 pending 文件。按 `c` 或关闭后，已落盘材料会保留。

- **首次下载中断**：保留 partial 文件；由于设备尚未返回完成游标，不能可靠推算起始绝对编号，下次重新读取最早仍保留的完整历史。
- **已有档案的增量同步中断**：根据已提交游标和 pending 条数恢复，不从头下载。
- **pending 有数据，但设备现在报告没有新记录**：这批数据缺少可确认的完成消息，软件会保留而不发布；等待设备产生新样本后再重试。
- **CSV 已提交，SQLite 没入完**：运行 `db` 或重新启动，软件会补入库。

从 0.5.0 起，增量暂存包含每次接收会话和持久化检查点。数据块和检查点都写入并同步后，才向设备确认接收。若进程在两次写入之间退出，下次会把超出可信边界的尾部另存为 `.unconfirmed-*.bin`，然后从已发布检查点恢复。

**升级前遗留的非空未完成 pending，如果没有这套连续块证据，软件会停止并保留文件，不猜测游标。** 已完整提交的旧档案继续兼容。出现该情况请保留整套材料进行独立核验，不要手动删除暂存来绕过提示。

### 提示校验和改变、游标冲突或数据库冲突

说明软件看到的历史与保存的状态不一致，继续拼接可能产生错误。保留现有 CSV、JSON 和数据库，按 `l` 查看完整原因。不要手动改游标或覆盖原文件来绕过检查。

### 提示 Another download / 数据库被锁定

同一设备或档案已有另一个任务正在处理。等它结束，或关闭另一个任务后再试。`.lock` 文件本身长期存在是正常现象，锁是否有效由操作系统判断。

### SQLite 文件不见了，但 CSV 和状态都在

运行 `db` 可从完整、校验通过的下载档案重建查询库。若数据库文件仍在但损坏，先保留整套文件再诊断；软件不会自动覆盖一个无法识别的数据库。

### 设备保存的记录变少，或者序列号没变但历史不连续

设备环形缓冲区可能已经覆盖旧数据，也可能发生了设备重置。软件会检查完成游标，不会把缺口静默当成完整连续数据。建议及时下载；本工具没有清空设备日志的命令。

### Git 能帮我备份观测数据吗

不能。Git 管理代码和文档，观测、数据库、抓包和运行目录均被忽略。数据备份请使用上面的 `backup` 和完整档案备份流程。

## 命令行速查

不熟悉命令行可以跳过本节，直接使用 TUI。下面命令均在项目根目录执行；自定义档案目录的 `--data-dir` 放在子命令之前。

```bash
# 打开中文界面
uv run kestrel.py

# 查看设备与入库状态 / 校验并补入库
uv run kestrel.py list
uv run kestrel.py status 2866855
uv run kestrel.py db

# 扫描
uv run kestrel.py scan --timeout 20

# 首次下载和以后增量使用同一条命令
# 不加 --execute 只显示预演，不访问蓝牙、不创建档案
uv run kestrel.py download --serial 2866855 --execute
uv run kestrel.py download --all --execute

# 从 SQLite 读取最近 20 条记录
uv run kestrel.py records 2866855 --limit 20

# 导出指定日期整天
uv run kestrel.py export 2866855 archive/exports/oct22.csv \
  --since 2026-10-22 --until 2026-10-22

# 数据库备份：不指定文件名时自动生成
uv run kestrel.py backup
uv run kestrel.py backup /实际路径/kestrel-backup.sqlite

# 导入已有完整下载；需要原始 .csv.json
uv run kestrel.py import /实际路径/my_history.csv

# 使用其他档案目录
uv run kestrel.py --data-dir ~/KestrelData list
```

`download` 还支持 `--timeout`、`--maxrows` 和单设备 `--ble-id`。默认上限是 6,220 条当次接收记录；它不是跨多次累计存档的总条数限制。

状态、扫描、预览、导出、入库检查和备份命令以 JSON 输出结果，诊断写入 stderr。退出码：0 成功或预演，2 错误或未完成，130 用户取消。批量同步中任何设备失败，整体返回 2。

供程序或 TUI 调用时，可以使用全局选项 `--events-json`。每行是独立的 JSON 事件，带 `version: 1` 与 `event` 类型；普通命令输出行为保持可用：

```bash
uv run kestrel.py --events-json download --serial 2866855 --execute
```

事件包括 `phase`、`progress`、`log`、`error`、`completed`、`result` 和 `finished`。收到 `completed` 代表该设备的完成结果，批量任务还需要查看最终 `result` 和进程退出码；`finished` 表示命令结束，不自动表示成功。

## 用 Git 管理代码

这个工作目录使用本地 Git 仓库管理代码、测试、依赖锁和文档。没有配置远程仓库，不会自动上传到 GitHub 或其他服务。

```bash
# 看改过哪些代码文件
git status

# 看具体改动
git diff

# 看已有版本
git log --oneline

# 修改并测试通过后，明确添加要保存的文件
git add kestrel_drop tests README.md docs pyproject.toml uv.lock CHANGELOG.md
git commit -m "描述这次代码改动"
```

`.gitignore` 排除了 `archive/`、个人历史资料、数据库、备份、抓包、`.venv/`、缓存及 `.env`。`.venv/` 仍可留在电脑上，不需要为保持 Git 干净而删除。分享或发布代码前可用 `git ls-files` 查看实际被跟踪的文件。

Git 提交保存的是代码版本；数据备份仍需单独进行。
