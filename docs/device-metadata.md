# 设备编号与当前领用管理

## 三种编号怎样区分

| 字段 | 例子 | 用途与规则 |
| --- | --- | --- |
| 设备序列号 serial | 2509793 | 厂家身份，SQLite主键和BLE核验依据；不可在资料页修改 |
| 管理编号 management_code | D1-006 | 课题组标签，独立保存，非空值唯一；首次保存后与序列号固定，不能修改或清除 |
| 当前受试者代号 participant_code | P001 / 0007 | 当前发放登记，可空；作为文本保存，前导零不会丢；允许同一人多台设备 |
| 设备别名 alias | 原有备注 | 与管理编号独立，导入标签不覆盖它 |
| 组合标签 | D1-006-2509793 | 由管理编号和序列号生成，不在数据库重复存一列 |

受试者代号只用研究代号，不填姓名、身份证号或联系方式。代码以字母/数字开头，可含字母、数字、下划线、点、短横线。管理编号最多32字符，保存时转大写；受试者代号最多64字符，保留大小写。空白去除，空字符串表示未编号或未分配。

## 在TUI中填写

1. 在设备列表选择一台设备。列表将管理编号、序列号、当前受试者分别列出，当前行详情也显示受试者代号。窄窗口用“…”标记过长字段，原值不被修改；按z可查看、编辑完整代号。
2. 按 **z** 打开本地资料。无需扫描或连接蓝牙。没有登记的扫描项需先按x核验登记。
3. 已编号设备的管理编号只读，只编辑当前受试者代号；未编号设备可首次填写管理编号，保存后锁定。用Tab/上下箭头切换，Ctrl+U清空输入。Enter在末项进入检查页。
4. 检查序列号、旧值和新值。再按Enter才保存；Esc返回修改，再Esc取消。受试者代号空值在检查页显示未分配。未编号设备可暂不编号；已经保存的管理编号不能清空。
5. 保存前会在事务中核对编辑时的旧值；若期间被另一操作更改则拒绝覆盖，刷新列表后重新编辑。保存后自动刷新本地列表。管理编号冲突会报错，整次修改不保存；不会悄悄覆盖另一台设备。

z只编辑当前行，与下载勾选名单无关；避免将一组不同设备误登记成同一受试者。也可以从设备配置页按z编辑该设备本地资料，不会触发设备设置写入。

## 导入已有编号表

CSV最少需要“设备序列号”“管理编号”两列；支持UTF-8 BOM。可带“编号”“型号”“设备别名”“受试者代号”。先预览：

```sh
uv run kestrel.py labels-import '/绝对路径/kestrel-labels.csv'
```

预览不写库。确认无误后：

```sh
uv run kestrel.py labels-import '/绝对路径/kestrel-labels.csv' --execute
```

已有编号必须与库中序列号的固定映射一致，预览阶段即拒绝重新编号；重复导入相同映射不会改号或新增审计。所有行通过检查后才在一个事务中保存。检查重复序列号、重复/已占用管理编号、未登记设备、型号和组合标签。不能借清单伪造硬件身份，未登记设备要先核验。导入不更新设备别名；没有受试者列或该列为空时，保留原有代号，避免重新导入标签时清空领用关系。非空受试者代号会更新并审计，先核对清单。要明确解除分配，请使用TUI或下面的metadata命令。

## 单台CLI编辑与清单导出

```sh
uv run kestrel.py metadata 2509793
uv run kestrel.py metadata 2509793 --participant-code P001
uv run kestrel.py metadata 2509793 --participant-code ''
uv run kestrel.py metadata 2509793 --management-code D1-006
uv run kestrel.py labels-export '/绝对路径/设备领用清单.csv'
uv run kestrel.py actions 2509793 --limit 20
```

metadata不带修改参数时只读；带参数直接保存，适合脚本，TUI另有确认页。管理编号参数仅用于首次赋号或重复提交同一值，不能用于改号、转移或清空已有标签；空字符串清除仅适用于受试者代号。导出的清单含六列：编号、管理编号、设备序列号、型号、设备别名、受试者代号。输出不覆盖已有文件，保存UTF-8 BOM。Excel直接打开CSV仍可能自动将0007转成7；需要保留文本时通过“从文本/CSV”导入，将代号与序列号列指定为文本。SQLite中的代号始终保留原文本。

## 发放、回收与换人

推荐发放前先下载一次，核对标签和序列号，再登记代号；回收时先下载、核对记录和实际佩戴时段，再清空代号或改为下一位受试者。配套发放记录应注明实际发放、佩戴和回收时段。

**当前代号不是全部历史观测的归属。** 设备可能带着前一位受试者甚至实验室阶段的旧日志，且设备校时可能让时间标签跳变。因此本版不会把当前代号自动追加到观测CSV，不提供据此归属全部历史的筛选，也不会改写已有观测。

每次资料改变都会原子保存旧值、新值与操作UTC时间，审计在device_actions的requested.local_metadata中识别。同值保存不新增审计。该时间表示登记操作发生的时刻，不等于开始佩戴或某一设备序号边界；不能直接拿审计时间切分受试者观测。需要正式按受试者/轮次分析时，必须结合实际发放表、佩戴时段及时间诊断，不能只JOIN当前devices表。

## 备份和隐私

设备资料在schema 5引入，当前schema 6另含自动同步偏好；设备表有两个TEXT资料列，并在非空管理编号上建立唯一索引。4→5升级前会在backups创建独立旧库备份，完整校验后再执行资料DDL，不改原始观测、下载游标或暂存块。只读旧库时不升级。旧版软件无法打开新版结构，回退需使用旧库备份，并妥善保留当前库的新数据。

资料、审计和备份都在本机数据库中。领用清单包含研究代号，按研究数据管理；放在数据目录exports/等已排除Git的位置。代码测试只用合成代号，真实清单与受试者信息不提交到公开仓库。

## 已贴标签后的扩充规则（0.14.1）

现有43台的管理编号与序列号以已登记映射为准，不根据序列号大小、型号、扫描顺序或CSV行号重新计算。新设备先核验登记，管理编号初始为空，再单独赋新号。按现有全局流水接续时，下一台可从044开始，例如新D2用D2-044；不要重新对所有设备排序后生成001起的编号。

首次赋号后立即固定；扫描、重复登记、下载、换受试者和清空受试者代号均保留该映射。离线或停用设备仍保留登记，其编号不能转给另一台。CSV中的旧映射如被排序脚本重新生成，预览与执行都会拒绝，执行阶段也有事务内复核，整批失败时不保存任何一项。

这里的保护适用于通过本软件的操作；不要使用旧版软件或直接编辑SQLite来改标签。恢复备份时应核对备份是否含已贴标签的管理编号；保留编号清单可用于恢复映射。误录后如确需维护，应先备份并核对实物标签，另行处理，不使用普通资料编辑绕过保护。

0.15起数据管理的两种清除均保留设备主键、固定管理编号、当前受试者代号及既有审计；不回收管理编号给其他设备。
