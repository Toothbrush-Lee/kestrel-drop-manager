# 设备时钟与采样时间

采样间隔、设备当前时钟、采样相位是三个不同属性。每300秒记录可以落在00:00:47、00:05:47；间隔符合5分钟，却未落在整5分钟网格。校时可能改变时间标签而不按电脑整点重新安排下一次采样，参数回读不能证明实际采样时刻正确。

## 使用与诊断

先下载并备份，再考虑校时或改间隔。TUI在设备列表或设置页按t，输入预期间隔；CLI运行：

```sh
uv run kestrel.py timing --interval 300
uv run kestrel.py timing SERIAL --interval 300 --recent 100
```

诊断只读档案，不访问蓝牙、不校时、不改记录。报告分开列出最近间隔是否一致、相对本地日历网格的偏移、完整历史中的重复时间/倒退/其他间隔，并列出最近1000条设置审计中含time的事件。已有档案可能没有最新设备记录，应先下载；预期间隔来自输入，不冒充现场设备配置。

长时间跳变并不自动表示丢记录，可能来自日期校正；相邻不同序号的相同时间也不自动表示重复数据。设备原始本地时间没有时区，单次校时偏移不能可靠换算整段历史为UTC。代码按设备序号保持原始顺序，不批量取整或回填历史时间。

## 校时保护

CLI校时须加--execute和--allow-schedule-shift；没有风险确认会在连接和建库前拒绝。TUI在预览风险后确认执行。批量逐台处理，不能假定多台同相位。

写前重新读RTC，now与新读值相差不超过1秒则不重复写；这属于减少不必要写入的秒级阈值，不是授时精度保证。审计保存新读值、目标、改变量和电脑带时区时间；只有时钟回读经过验证，sampling_risk.schedule_alignment_verified仍为false。必须观察之后至少两条新历史才能讨论相位是否符合要求。

## 设置写入保护

DROP设置使用官方逐字段忽略标记，未选择的间隔、覆盖策略、实时更新率、安全级别、Setup Complete和参考海拔不会被原值重新写入；未用字节保留。请求中的ignore字节不等于设备实际状态，期望回读单独构造。相同设置值不发送写入，仍读回确认。不能用同值设置作为强制重启计时器的隐式手段。

历史采样与实时更新率不同；关闭滚动覆盖后满存会停止追加记录，开启覆盖会淘汰设备最早记录。校时、换电池、间隔变化、其他客户端设置和电脑时区/DST变化均应作为时间质量检查的触发点。写入中断不等于回滚，失败/取消后先读取设置与审计，不自动重复写。

## 设备端恢复相位

提供的协议没有直接设置下一采样时刻的接口。暂停记录、在目标边界恢复原间隔是候选实机方案，会改变采样节奏、可能形成缺口；必须先备份并针对一台取得明确授权。若还需校时，也要明确覆盖这项额外写入。失败时首先恢复原间隔并回读，不能清日志或恢复出厂。

只有观测到至少两条新记录都在目标网格、间隔正确，才能标记该次实测成功。某型号/固件的成功不能直接推广到其他型号/固件，更不能由一次CLI ACK或设置回读推断成功。

## 软件验证

离线测试覆盖“间隔正确但相位偏移”、跨日、倒退与重复时间、只读诊断、CLI/TUI风险确认、ignore设置的回读、同值不写、接近同步不写时钟及大改时钟的审计证据。测试不修改工作档案或模拟成实机保证；实际设备试验日志另存于本地data/analysis。
