# 0.15 数据管理验证

验证日期：2026-10-30。按本轮要求不实现GPS。功能和操作入口见[数据管理](data-management.md)。

## 协议与交互

对照官方LiNK手册第21页，以及本地355207 Rev G、355204 Rev AC协议。电脑历史与设备内部日志分开；自动同步是连接时同步，默认关闭；实时传输速率与日志采样间隔分别设置。设备擦除使用命令1，ACK后用命令2读取总条数，不写时钟或停止采样。

h页首先只查SQLite，不扫描。设备目标固定，设置必须先读取；清除必须输入完整厂家序列号并再次确认。未知结果不自动重试，可用c独立只读查询设备条数。备份路径保留在任务日志。

## 自动验证

- 完整环境393项测试全部通过；无浏览组件的隔离环境同一测试集通过，4项可选界面测试跳过。
- 覆盖schema 2/3/4旧库兼容、schema 5只读与5→6独立备份升级、DDL失败回滚。
- 覆盖默认关闭的逐设备偏好、同值不重复审计、单连接自动同步、同步失败禁止继续设置、扫描登记同步失败仍保留已核验身份。
- 覆盖电脑历史清除的独立备份校验、过期确认拒绝、事务失败回滚、仅目标设备被清除、标签/受试者/偏好/其他设备保留、下次下载开启新历史段。
- 使用真实协议编码的模拟BLE，验证设备清除前先同步与备份、硬件身份不符/待确认/备份失败时不擦除、匹配ACK后严格检查0条、后续下载沿生命周期序号继续。
- 注入ACK丢失、取消、擦除后新增记录、审计写失败；均不重复擦除，不删除电脑已保存数据。
- 覆盖真实worker→CLI→临时SQLite→TUI刷新，输入与二次确认，18行×68列布局、后台结果校验、清除失败不提供自动重试。
- Ruff、版本一致性、wheel/sdist内容审计、隔离安装CLI/TUI冒烟、macOS ARM独立包构建与冒烟通过。发布流水线另行验证Linux及两种Mac架构。

## 现有档案副本

正式库包含43台设备和264,312条观测。先建立独立SQLite副本，再在副本验证schema 6升级；devices、histories、transfers、pending_blocks、observations、device_actions按确定顺序逐行摘要前后相同。

仅在可丢弃副本中开启一个设备的自动同步偏好并清除其14,795条本机记录，核对该设备标签和偏好保留、其他42台记录不变；独立备份仍保有原记录，并可完整恢复到空目录。测试结束核对正式库六张表摘要不变。

真实TTY只打开本机h页，确认D1-001的管理编号、末条时间和4,658条记录正确显示，然后返回退出；未操作实机或正式库清除。

## 验证边界

本轮没有向真实设备发送擦除指令。不同固件实际擦除及清除后采集仍需使用可清理的测试设备验证。持续采样时，最后同步与擦除之间可能出现新记录；没有为了规避该窗口而隐式停采、校时，也不承诺零丢样。

正式库保持原样；首次需要写入或显式migrate时自动备份并升级schema 6。升级后应使用0.15或更新的采集程序。所有档案副本、研究资料和本地构建产物均不提交公开Git。
