# 多型号识别与多设备采集审查（0.6.1）

本轮解决 D1/D2 编号读取、型号显示及混合设备管理问题。D1/D2/D3 均支持广播识别、标准 GATT 身份核验和登记；历史下载目前仅验证 D3。数据库继续使用 schema 2，不重建或迁移已有观测。

## 审查发现与修复

| 问题 | 影响 | 本轮修复 |
| --- | --- | --- |
| 广播编号正则只匹配 D3，过滤条件漏掉部分 D1 | D1/D2 有完整广播名称仍显示无编号 | 统一 D1/D2/D3、大小写、常见分隔符；未知格式不猜编号 |
| 连接前寻找设备的名称写死 D3 | D1/D2 仅凭编号无法定位 | 通用解析器按编号或临时 BLE 地址寻找，新地址可按编号重新解析 |
| 未命名候选要求手工输入序列号 | 用户难以区分多台设备 | x / identify 读取标准型号与序列号字段，核验后 register 登记 |
| 界面和导出名称写死 D3 | 型号混淆、能力误导 | 独立型号列，标明广播提示与核验状态，明确“历史待适配” |
| 扫描结果按编号覆盖 | 重复编号或地址复用可能合并错误行 | 冲突保留多个候选，阻止按编号盲选；旧档案统计不转移到新设备 |
| 同步全部仅包含有正式记录的设备 | 初次中断、已登记但空档案被遗漏 | CLI --all 包含登记库；TUI 支持勾选并处理当前列表的新设备 |
| 批量丢失单台 BLE 地址 | 自定义名称设备在后台无法定位 | --serials 与 --ble-ids 一一对应，校验数量、编号重复与地址冲突 |
| 每台重复完整扫描 | 100 台任务扫描开销过大 | 一次共享扫描，顺序连接；快照未发现的设备才重新寻找 |
| 一台 pending 损坏导致全部 status 失败 | 健康设备也无法采集 | 状态逐台报告异常，下载读取目标设备自己的正式状态；完整检查仍报告全库错误 |
| 型号判断采用子串 | DROP 30 等可能误套 D3 | 精确型号解析；身份、下载、旧协议入口均设型号边界 |
| 取消批量的边界需要明确 | 可能误启动后续设备或缺少退出事件 | 取消返回 130，保留已落盘块，不继续启动下一台 |

广播名称和 BLE 地址都不是入库身份的最终依据。下载前必须读回型号和真实序列号；不匹配、未知格式、尚未支持的型号会在历史命令发送前退出。不会用蓝牙 MAC/UUID、广播随机字段或列表行号代替设备编号。

## 使用方法

TUI：s 扫描 → 查看型号与编号 → 编号未知时 x 核验登记 → 空格勾选 → a 顺序采集。没有勾选时，a 处理当前列表中所有编号已知且无身份冲突的设备。D1/D2 单台下载会显示待适配说明；混合批量中的不支持/失败项会单独报告，继续处理其他设备。

```bash
# 只扫描广播
uv run kestrel.py scan
# 逐台只读核验，不登记、不下载
uv run kestrel.py scan --identify
# 同一轮扫描中核验并登记，不重复扫描每台设备
uv run kestrel.py scan --register
# 单设备查询与登记
uv run kestrel.py identify --ble-id BLE地址
uv run kestrel.py register --ble-id BLE地址
# 明确的设备列表，或所有本地登记设备
uv run kestrel.py download --serials 2866855 3087666 --execute
uv run kestrel.py download --all --execute
# 自定义名称：按列表传入临时定位地址，连接后仍验证序列号
uv run kestrel.py download --serials 2866855 3087666 --ble-ids 地址一 地址二 --execute
```

--ble-ids 中的 `-` 表示按编号寻找。不保存 BLE 地址为永久身份，重新扫描可刷新地址。重启后自定义名称设备应重新扫描/核验再选择；CLI --all 不会凭空推断未广播编号的自定义名称设备地址。

scan --identify / --register 中单台连接失败仍返回其他设备结果，同时报告非零退出码。register 只增加本地设备/空历史段，不能据此认为已有观测或已支持该型号历史格式。未完成初次下载与零新增任务保持原有恢复和幂等语义。

## 验证

174 项测试在 Python 3.14.3 与 3.15.0 上通过，包含原有持久化与迁移测试，以及本轮 40 项多设备测试：

- D1/D2/D3 广播解析、标准 GATT 核验、缺失/非法编号、型号冲突，身份流程不调用写指令。
- 100 台批量只进行一次共享扫描，正确保留序列号与临时地址对应，单台失败后继续。
- 重复编号/地址、地址变更和复用、自定义名称、扫描快照后新出现设备。
- 真实协议模拟采集两台 D3 到独立历史段，原始字节与各自游标不串库。
- D1 与 D3 混合批量明确拒绝 D1 历史命令，D3 正常完成；取消后第二台不启动。
- 受损 pending 不影响另一台状态/下载；完整 db 检查与备份仍拒绝损坏的库。
- 空格勾选、批量参数传递、未知编号 Enter 核验、型号列、扫描合并与冲突提示。
