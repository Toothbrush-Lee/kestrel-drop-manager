# 0.12.1 校时与采样安全验证

2026-10-28，schema 4不变。问题是“时钟回读正确”与“后续采样落在整点”此前未明确分开。用户档案的一致快照已只读检查，原始记录本身含相位偏移，连续序号未被时间跳变打断；详细设备数据和审计保留在本地data/analysis/clock-sampling-20261028，不上传观测或官方原件。

## 官方依据

核对355204 Rev AC的通用时间命令与DROP专用表93–96、355207 Rev G的历史序号和DROP间隔定义、355215 Rev L的传输约束及LiNK Security Rev C的权限边界。通用/其他产品的命令字节不能直接套用到DROP；文档没有承诺Set Time自动对齐采样定时器，也没有下一采样时刻的直接接口。

## 实现

- timing CLI及TUI的t入口只读诊断；预期间隔明确为用户输入，不冒充设备当前配置。原始记录按序号保留，不四舍五入、不按时间戳去重。
- CLI执行time需要显式--allow-schedule-shift；缺少确认在蓝牙和建库前拒绝。TUI预览说明相位、跳时、重复时间和机群不同步风险，确认后才执行。
- 写前重新读RTC，记录改变量、目标与电脑时区。now误差不超过1秒则跳过重复写；回读成功仍标记相位未验证。
- DROP设置用官方ignore标记排除未选字段，同值不重写；期望实际回读独立构造，不能拿ignore请求字节与设备实际状态比较。
- 官方数据和时钟字节序的固件差异沿用已印证的处理，不盲目切换；没有新增默认停止日志、恢复出厂或清除历史操作。
