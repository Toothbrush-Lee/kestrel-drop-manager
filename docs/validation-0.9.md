## 0.9.1 扫描等待优化 — 2026-10-27

发现根因：已知 BLE 地址仍使用定时 discover，必须扫描满 20 秒才返回；列表扫描默认 15 秒。每次配置操作为独立子进程，不能直接复用上一进程携带系统状态的 BLEDevice。

修改为按地址发现即返回，复用同一查找窗口的广播处理旧地址回退；共享批量快照命中时不启动扫描。只有序列号时仍完整扫描检查重复身份。TUI/CLI 列表扫描默认 5 秒，TUI 大写 S 显式长扫描 20 秒。连接后型号和真实编号仍重新核验，不修改配置写入及回读规则。

240 项测试在 Python 3.14.3 / 3.15.1 通过；新增 10 项覆盖提前返回、快照零扫描、旧地址回退、重复编号、缺失目标不再扫描、取消传播、CLI 默认与 TUI 长扫描及配置地址传递。此处验证调用和终止条件，没有实测蓝牙延迟，5 秒快扫也不能保证发现全部设备。

本次未连接真实设备，测试仍使用隔离目录。与上一轮 0.9.0 验收相比，55 个原件、备份和其他受保护文件校验和不变；运行库已增加 24 条正式观测至 35,646 条，最近会话显示完成于本地 00:39 左右。这些现有采集更新保持原状，不回滚，也不把旧库校验和当作本轮开始时的基线。日志和摘要在本地 ui-0.9-20261027 目录中另存 scan-0.9.1 文件。

## 0.9.2 完成事件误报修复 — 2026-10-27

用户报告三台设备完成事件被判为“后台事件格式错误”。根因是 worker 把所有 code 都当作字符串校验，而管理器的 completed 合法使用整数 0/3；error 才使用符号字符串。此校验位于 TUI 后台接收侧，不是设备传输或数据库事务中的校验，误报没有撤销已经完成的入库。

修复为按事件类型验证 code。新增 8 项测试，其中三台成功事件通过真正的 Library.complete_download 与 events.stream 生成，再通过 Job 读取线程和 Terminal.poll 检查：三台完成被接收、条数逐台刷新、最终退出码为 0；待确认仍为未完成，畸形事件仍被拒绝。Python 3.14.3 / 3.15.1 共 248 项测试通过。

只读核查报告设备的正式条数与末条时间：2509793 为 13,988 / 2026-10-27 00:35:47，2525425 为 8,490 / 2026-10-27 00:34:30，3087666 为 6,958 / 2026-10-27 00:37:08，与报告一致。修复无需重新下载或迁移。本次不连接设备，测试使用隔离默认数据和配置，运行数据库的前后校验和核查另存本地 event-0.9.2-acceptance.json。
