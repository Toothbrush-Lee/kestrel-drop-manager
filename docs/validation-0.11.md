# 0.11 验收与性能对比

日期：2026-10-27。落实 [0.10 性能报告](performance.md)的五项优化。SQLite 保持 schema 4，升级不迁移观测数据；原有多选、标准扫描和配置确认流程保留。

## 实施内容与结构

| 范围 | 实现与边界 |
| --- | --- |
| 批量定位 | 单台和多台复用 locate_snapshot；全部目标有地址时，发现全部地址后返回，同一窗口仍保留旧地址回退线索。含仅编号目标时完整扫描。标准 s 扫描仍为 15 秒，连接后仍核验身份。 |
| 状态查询 | status(serial=None) 共享一条实现，只用 SQL 缩小设备范围。完成结果和零新增判断不再校验其他设备暂存；本设备的恢复边界与错误处理保留。没有新增条数缓存或冗余数据库字段。 |
| 界面 | active_drawer 统一选取顶层页面；needs_redraw 由输入、事件及窗口变化触发。运行中的主页面动画限制为约 4 次/秒，输入等待仍为 100 ms。文本按内容与宽度缓存折行，关闭文本释放缓存。 |
| 配置 | 同一连接内复用成功读取的固件/硬件字段，失败值仍重读；设置、名称和电量等动态值继续读取。已完成偏差核验的时钟回读复用于结果，避免再读一次。身份核验、保留字节核对、独立审计仍执行。 |
| 导出 | iter_query 在同一只读事务内按 1,000 行读取；query 保留原有列表接口，限量预览保持顺序。CSV 逐条输出、计数，关闭/失败/取消时释放快照并清理临时文件；仍使用 UTF-8 BOM、日期边界、fsync 和不覆盖发布。 |

配置成功结果另含 timings_seconds，按实际执行情况记录 locating、connecting、identity、read_before、write_verify、audit、total，单位秒；批量设置成功项透传本设备计时。total 包含清理等阶段，不要求等于各子项之和。计时不进入或改变原有配置前后审计证据。

## 相同数据与方法下的性能

基线来自已提交的 0.10.0（1dcc441）；在临时目录展开该版本源码，用同一版基准脚本运行。实际档案先生成一份固定、只读来源的临时快照，再同时用于前后测试，避免把采集条数变化当作优化结果。该快照为 4 台 / 36,183 条；百台场景由相同生成规则构造。

环境为 Python 3.14.3 / SQLite 3.50.4 / macOS ARM64。均为预热后的中位墙钟时间，样本数与限制沿用原报告；原始逐次结果位于本地 data/analysis/performance-0.11-20261027/。以下不是 BLE 端到端吞吐成绩。

| 同一项操作 | 0.10 基线 | 0.11 | 解释 |
| --- | ---: | ---: | --- |
| 百台百万条，一台完成结果整理 | 16.04 ms | 0.38 ms | 不再遍历其他设备 |
| 百台百万条，逐台整理全部结果 | 1,589.17 ms | 38.18 ms | 约 42 倍局部改善 |
| 另有 8 台各 1 万条暂存，单台完成整理 | 123.92 ms | 0.35 ms | 不再解码其他设备暂存 |
| 500×1,000 字符日志，缓存后重绘 | 44.01 ms | 0.126 ms | 复用折行并只绘制顶层 |
| 同一长日志首次打开折行 | 43.63 ms | 45.18 ms | 首次排版仍需计算，没有同倍提速 |
| 百台百万条，最近 100 条查询 | 1.21 ms | 0.79 ms | 避免重复统计后读取 |
| 每台 1 万条，导出峰值 Python 分配 | 10.17 MiB | 0.93 MiB | 改善主要是内存约束 |
| 每台 1 万条，完整 CSV 导出 | 46.09 ms | 44.79 ms | 耗时大致相当，不宣称大幅提速 |

当前真实快照的第一台导出峰值约由 12.76 MiB 降至 0.74 MiB。以上内存是 tracemalloc 的 Python 分配峰值，不是进程 RSS。合成数据有重复合法时间，不用于判断日期索引选择率。

每块完整持久化中位由约 0.75 ms 到 0.70 ms，最终发布约由 17.7 ms 到 16.4 ms；这是正常环境波动，持久化代码未修改，不作为优化收益。CRC、原始记录一致性、FULL 同步、事务后 ACK、完成确认、恢复检查与备份验证继续保留。

批量定位没有恢复快扫，也没有通过并行扫描和接收提速：这里只验证“全部指定地址到达即停止”的条件。实际节省秒数取决于广播和系统，需现场实测。配置校时模拟从三次 Get Time 减为两次，仍包含写前读取和写后核验；固件、硬件各从两次读取减为一次，仅在同一连接复用。

## 回归与交互检查

293 项测试在 Python 3.14.3 与 3.15.1 上通过，包括原有 268 项和新增 25 项：

- 批量地址全部到达才结束、地址大小写与重复、漏扫保留线索、仅编号完整窗口、取消不另起扫描；CLI 地址完整与混合目标走正确分支。
- 局部状态等于全库筛选；完成一台时不解码另一台；本台损坏暂存仍被发现，首次待确认数量和恢复位置一致。
- 流式与列表记录顺序、筛选和原始字节相同；CSV 字节与旧格式一致；跨批读取期间有新数据提交，导出仍保持原快照。
- 提前关闭读取、写文件失败和用户取消均释放连接，目标及临时文件不残留。
- 文本缓存处理原地内容变化、重新打开日志与窗口宽度变化；不绘制被覆盖的列表；空闲超时不重绘，输入/窗口变化仍更新，运行动画受限且 q 能取消。
- 稳定字段复用、动态电量重读、稳定字段首次失败后重试；真实控制层的时钟写入及偏差核验继续执行；阶段计时不改变审计内容。

在真实 PTY 的 68×18 窗口检查启动、后台 list、空闲显示、帮助折行和返回、表单光标编辑与退出。使用独立空数据目录及设置文件，不扫描、连接或写入真实设备。模拟性能与 PTY 检查不能替代各种固件的实机验证。
